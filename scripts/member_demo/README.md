# 本地成员维护演示

用虚构成员试用“填写 → 审核 → 预览 → 应用 → 成员展示”。不读取或修改正式 `content/`、`site/` 数据。

## 启动与停止

在项目根目录运行，使用现有 Python 3.11 或以上版本，无第三方依赖：

```sh
python -B -X utf8 scripts/member_demo/server.py --port 8766
```

打开 <http://127.0.0.1:8766/>。前台启动时按 Ctrl+C 停止；端口占用时可用 `--port 8767`，并打开对应地址。服务仅监听本机回环地址。

测试状态默认保存在 `.local/member-demo/`，刷新页面或重启服务后继续保留。使用 `--data-dir .local/自定子目录` 可建立独立试用副本，不能指定项目外或正式内容目录。

## 三分钟体验

1. 在“学生填报”使用预填的“示例同学甲／硕士／2021”，勾选毕业确认，提交申请。
2. 点“去维护者审核”，确认匹配的是其2021级硕士经历，将审核结果改为“通过”，保存。
3. 点“查看修改预览”，核对毕业确认变化，再点“应用到测试数据”。
4. 点“查看成员展示结果”，在绿色计算方向展开硕士的“已毕业”，查看“示例同学甲（21硕）”；其2024级博士经历仍展开显示。

可继续试用“新增经历”的预填示例，给示例同学乙增加博士经历；或使用“修改资料”更新其个人主页。姓名和主页由各段经历共用，方向及毕业确认属于某一段经历。跨方向成员会在相关方向分别出现。

## 处理规则

- 申请初始为待核对。“通过”只保存审核决定，预览并应用后才改变成员展示。
- 同名或无法唯一匹配时，维护者须明确选择人员和经历；错误或无匹配的申请可以暂留待核对或退回。
- 应用前测试资料发生变化，须重新预览；已应用申请不能再次应用。
- 修改时空白保留原值；清空主页、方向或博士后年份需显式勾选。硕博年份不能清空。
- 同一成员新增经历时保留旧经历与现有主经历。博士后离站不按毕业处理。其他往届经历仍显示在“往届成员”，不会自动成为已毕业。
- “重置演示数据”经确认后恢复预置虚构成员，清空当前申请列表；原状态仍保存在本地备份中。

## 导出与本地材料

审核入口的两个 CSV 导出按钮分别保存申请记录和带审核信息的记录，文件位于当前数据目录的 `exports/`，页面会给出查看入口。文本为带 BOM 的 UTF-8，方便表格工具打开。

这些是平台无关的申请／审核导出样例，尚未接入云表单，也不是现有正式成员导入器的输入格式。具体厂商字段映射及正式数据迁移待体验验收后实现。

`state.json` 同时保存人员、经历、申请和操作记录；每次变更原子替换文件，先前内容保留在 `backups/`。写入失败保留原文件，后续可重试。运行材料由 `.gitignore` 排除，正式源码与虚构样例可纳入版本管理。

三个入口只是测试角色切换，不提供真实登录或权限隔离。只用于本机虚构数据试用。

## 验证

```sh
python -B -X utf8 -m unittest discover -s scripts -p "test_*.py"
```

申请逻辑在 `core.py`，不依赖 HTTP；虚构初始资料在 `fixtures.py`；HTTP 入口在 `server.py`；成员预览为服务端生成的 HTML，分组使用原生 `details`，单独打开 `/members` 后关闭 JavaScript 仍可展开。
